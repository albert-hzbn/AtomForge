\chapter{Getting started}\label{ch:start}
\section{What AtomForge does}
AtomForge is a desktop structure builder and viewer with a native electronic post-processing engine. It constructs atomistic starting configurations, edits positions and cells, renders structures, measures geometric quantities, and processes scalar fields from electronic-structure calculations. It does not run a self-consistent electronic calculation, relax a structure, or predict a formation energy merely by building a model.

The main structure workspace and the electronic dialog maintain different data. Opening a CIF in the main workspace supplies atom positions and a cell. Opening CHGCAR in \ui{Analysis > Electronic Structure > Electronic Post-Processing} supplies a sampled scalar field and imported sites. A structure alone does not contain a charge density; a rendered mesh alone does not contain an electronic wavefunction.

\section{First structure: a copper crystal}
\begin{enumerate}
\item Start the executable. Choose \ui{Build > Bulk Crystal}. Select the cubic crystal system and space group 225.
\item Enter $a=3.61$ \angstrom. Use a Cu site at fractional coordinates $(0,0,0)$ in the asymmetric-unit list. Remove unrelated default sites if present; do not add the three symmetry-equivalent FCC positions yourself.
\item Build the crystal. Inspect the generated structure and its cell. The supplied example \code{examples/cu_fcc.cif} has four Cu atoms in the conventional cubic cell.
\item Close the builder when finished. Use \ui{View > Structure Info} to inspect counts and lattice information.
\item Choose \ui{File > Save As}, browse to your work folder, enter a new filename such as \code{cu_first.cif}, select CIF, and save. Reopen the saved file to check that the cell and species are retained.
\end{enumerate}
If symmetry support is unavailable in a custom build, install/build with spglib or open the supplied expanded CIF instead. The lattice parameter is an example input; select a parameter appropriate to your intended temperature, composition, and calculation method.

\section{Opening, saving, and browsing}
\ui{File > Open} reads a structure into the workspace; \ui{Open Recent} returns to previously used paths. The browser supports directory navigation and file selection. Double-click a directory to enter it, select a file, then use the dialog's opening action. The location field is useful for jumping to a directory; it is not necessary to type the entire file path.

\ui{Save} writes the active structure to its current destination. Use \ui{Save As} to preserve the original and choose a new filename/format. A structure save records supported structural data, not every display setting or electronic intermediate. Save derived electronic grids separately from the electronic dialog. \ui{Close} closes the current structure; \ui{Quit} exits the program. Save valuable edits before closing.

\section{File types and what survives export}
The desktop opens XYZ and extended XYZ (\code{.xyz}, \code{.extxyz}), CIF, VASP, LAMMPS data (\code{.data}, \code{.lmp}), PDB, SDF, MOL, MOL2, PWI and GJF files. XYZ, CIF, VASP and LAMMPS data are read and written by AtomForge itself at full precision (CIF in P1 with fractions to twelve decimals; POSCAR with the species on the title line and Direct coordinates; LAMMPS data in the atomic style, each mass followed by its element, with the cell rotated into LAMMPS's frame and, for a structure without a cell, a box with 10 \angstrom{} of space around it); the other formats (and a CIF with only Cartesian coordinates) go through Open Babel. LAMMPS data is read in the atomic, charge, molecular and full styles (from the comment after \code{Atoms}, else from the number of columns; six columns that could be either charge or molecular must be named), with a triclinic box and each type's element from a label after its mass (\code{1 63.546 \# Cu}) when the label's element has that mass (force-field names such as CA or HO are not elements), an \code{Atom Type Labels} section, or else the mass. Extended XYZ columns may come in any order (\code{Properties=id:I:1:species:S:1:pos:R:3}). Structures of up to five million atoms open for editing; larger XYZ files open as atom clouds. Select a format for the information you need: CIF or VASP for periodic cells, XYZ for simple coordinate interchange, and a molecular format for molecular connectivity where supported. A CIF is expanded by its listed symmetry operations or, when it lists none, by the space group it names (Hall symbol, Hermann--Mauguin symbol in its short or full form, with a setting such as \code{:2}, \code{:H} or ICSD's \code{Z}, or number). Without a setting, a rhombohedral group uses hexagonal axes when the cell is hexagonal, and a group with two origin choices the one that puts the fewest atoms in the cell (origin 2 when both give the same count, which the message after opening mentions); a name that is not recognised is refused rather than read as P1. Symmetry images of one site closer than 0.1 \angstrom{} (special positions written with rounded coordinates, such as 0.333 for 1/3) are one atom. Elements are read from the type symbol, else the label, in any case and with charges (\code{CA}, \code{Fe3+}, \code{O2-}); a site whose element cannot be read is refused. A file with several data blocks opens its first structure and says how many there are. Sites with occupancy 0 are left out; magnetic CIFs are expanded by their operations and centerings (time reversal ignored); CIF 2 triple-quoted strings are read. XYZ files keep a cell as extended XYZ: \code{Lattice="..."} on the comment line is read, and saving a periodic structure as XYZ writes it (with \code{Properties} and \code{pbc}). Element symbols in XYZ may be in any case (\code{CU}, \code{cu}). XYZ is written with ten decimals and the structure's own atoms (with the cell when periodic), not the periodic images the view adds at the cell faces. CIF and VASP files need a unit cell: saving a structure without one is refused with an explanation (save it as XYZ, PDB or MOL, or add a cell with \ui{Edit > Structure Operations > Add Vacuum}). VASP files are recognised by a \code{.vasp} extension or by POSCAR or CONTCAR anywhere in the name (\code{Cu_POSCAR}, \code{POSCAR-001}); a negative scale factor is read as the cell volume, and a VASP 4 file without an element line takes its species from the title line (``Na Cl''). Selective-dynamics flags are kept: each atom remembers which coordinates are fixed through edits, supercells and project files, \ui{Atom Info} lists them, and a POSCAR is saved with them (\ui{Edit > Structure Operations > Fix Atoms} and \ui{Free Atoms} set them on the selected atoms, and the selection variable \code{fixed} counts an atom's fixed coordinates). A CIF with several species on one site (partial occupancy, as in a disordered alloy) opens with one atom per site, the species with the largest occupancy; one species split over nearby positions (within 0.5 \angstrom{}, occupancies adding up to at most 1) keeps one of them; the message after opening says how many sites were resolved. \ui{Build > Substitutional Solid Solution} then makes a random arrangement with the intended composition.

Plain XYZ does not reliably communicate a periodic lattice to every downstream reader. PDB has format-specific field limits. Format conversions may not preserve custom atom colours, grain identifiers, overlays, or all calculation metadata. Check the exported file in the program that will consume it, especially after transforming a non-orthogonal cell.

Electronic inputs are a separate family: VASP charge/potential/ELF grids, Gaussian Cube, and XSF datagrids. Electronic outputs include XSF, Cube, and VASP grids; CSV tables; and OBJ/PLY isosurface meshes. A CSV profile is a numerical table, while an OBJ surface is geometry. Neither is a replacement for saving the full scalar grid.

\section{Drag and drop}
With the electronic dialog open, drop a supported volumetric file onto the application to load it there. Enable \ui{Drop files as reference} before dropping an operand density. Files arriving during a calculation are queued; wait for the active calculation to finish before interpreting the new field selection. A reference-file drop supplies the second input; it does not subtract anything until you choose and calculate an operation.

Several structure builders accept dropped structures or meshes in their own preview/source regions. Use the visible drop guidance in the active dialog. For an unambiguous workflow, open only the builder you intend to supply and verify the displayed source filename and atom count immediately afterwards.

\section{The main window}
With nothing open, the window shows a welcome panel: \ui{Open Structure}, \ui{Build Crystal}, \ui{Open Project}, \ui{Read Manual}, example structures to open with one click (copper and iron cells, a Cu--Ni alloy, a grain boundary, a polycrystal, a dislocation, a nanoparticle and amorphous SiO$_2$, installed with the manual in an \code{examples} folder) and the recently opened files (a file that has since been moved or deleted is greyed out). Files can also be dropped anywhere on the window.

The toolbar under the menus groups the common actions: \ui{Open} and \ui{Save}; undo and redo; \ui{View} (look along x, y, z or the lattice vectors a, b, c, and reset the view); \ui{Rotate} (an angle and the axis to rotate the crystal about); \ui{Measure} (\ui{Distance} and \ui{Angle} between picked atoms); \ui{Select} (\ui{Box} and \ui{Lasso} selection modes, highlighted while on; drag in the view, with Ctrl to add). On the right, \ui{Commands} (Ctrl+K) searches every menu command by name, \ui{Pipeline} opens the structure pipeline, the projection button switches between perspective and orthographic projection, and the theme button switches between the light and dark themes. Every button explains itself in a tooltip, with its keyboard shortcut; in the builder and editing dialogs, hovering a field shows what it controls (the same explanations as the control reference in Chapters 2 and 3). In a narrow window the toolbar wraps onto more rows.

Resting the mouse on an atom in the view names it in a tooltip: element, index and position (structures above 100\,000 atoms skip this, as they skip picking).

The status bar along the bottom shows the file, the number of atoms, the selection (the element, index and position of a single selected atom, or the count and the most common elements of several), the cell lengths, the projection and the colouring; clicking the projection switches it, and clicking the colouring offers the colour modes.

\paragraph{Docking, collapsing and minimizing windows.} Tool windows that stay open beside the view (\ui{Structure Pipeline}, the scientific tools, \ui{Trajectory Playback}, the post-processing windows and the one-step operations) dock: drag one by its title bar onto the arrows that appear at the sides of the view, or onto another window to make them tabs. The 3D view then fills the space that is left, centred in it, and the layout is kept for the next session. \ui{View > Dock Structure Pipeline at the Right} docks the pipeline in one step, and \ui{View > Reset Window Layout} floats every docked window again. The arrow at the left of a tool window's title bar (or a double click on the title) folds it to its title bar. The large builder and analysis dialogs (the crystal, nanocrystal, polycrystal, grain-boundary, interface, stacking-fault, custom, solid-solution and amorphous builders, \ui{Insert Dislocation}, \ui{Add Interstitial Atoms}, \ui{Merge Structures}, \ui{Cell Sculptor}, and the RDF, ADF, CNA and short-range-order analyses) have a minimize button (\textendash) beside their close button: the dialog is hidden with all its settings, a bar above the status bar lists it, and clicking its name there brings it back.

A structure with unsaved changes shows a dot on its tab and in the window title (undoing back to the saved state clears it). Closing such a tab asks whether to save it first (\ui{Save}, \ui{Don't Save} or \ui{Cancel}; \ui{Save} on a new structure opens \ui{Save As}), and closing the window lists the structures that would lose changes before quitting.

\section{Orienting and inspecting the main view}
Use the toolbar's X, Y, Z buttons (keys 1, 2, 3) for Cartesian-axis views and a, b, c (Shift+1, 2, 3) for lattice-direction views when a cell is available. The rotation angle and the adjacent axis buttons apply a repeatable rotation. \ui{View > Reset View} (key R, or the toolbar's home button) restores framing; it does not undo atom edits. \ui{View > Projection} chooses \ui{Perspective} or \ui{Orthographic}. Use orthographic views when comparing projected distances or alignments.

\ui{View > Show} gathers everything that can be shown or hidden: \ui{Atoms}, \ui{Atom Labels} (with \ui{Label Atoms With} choosing the element, the per-atom property value, both or the atom index), \ui{Element Legend} (on by default: when atoms are coloured by element and there are several elements, a card at the top left of the view lists each element's colour and atom count; clicking an element selects its atoms, Ctrl adds them to the selection), \ui{Bounding Box}, \ui{Lattice Planes}, \ui{Miller Directions}, \ui{Voronoi Volumes} and \ui{Dislocation Lines}. \ui{View > Colour Atoms By} switches colouring between elements, crystal orientation, grain boundaries and a per-atom property. Orientation/boundary colouring requires corresponding structure metadata; a plain XYZ file may not contain it.

\ui{View > Atom Style} offers balls, ball-and-stick, space-filling, and polyhedral representations when supported by the current state. Bond-like lines and coordination polyhedra are visual/geometric constructs based on neighbourhood criteria; do not infer a quantum-mechanical bond order from their appearance.

\section{A productive project layout}
Create separate folders for input calculations, generated structures, derived fields, tables, and figures. Keep original electronic outputs unchanged. Name derived fields by operation, for example \code{AB_minus_A_minus_B.xsf}, and record the reference weights, grid geometry, selected channel, and units beside numerical results. For publication, retain the actual density difference and quantitative tables as well as the screenshot.

The folder containing this manual follows that pattern on a smaller scale: \code{chapters/} holds editable LaTeX, \code{figures/} holds published illustrations, \code{examples/} holds reusable structures and tables, \code{scripts/} holds regeneration tools, and \code{build/} holds disposable LaTeX/render intermediates.
