\chapter{Editing, assembly, and defects}\label{ch:editing}
\section{Selection and edit history}
Click an atom in the main scene to inspect/select it. Left-drag orbits the camera; right-drag normally pans. When \ui{Edit > Box Select} is active, right-drag draws a selection rectangle instead. \ui{Lasso Select} uses a right-drag path for a more irregular projected region. Selection is based on the current projection, so inspect the result from another direction before acting on a dense or overlapping set of atoms. Selected atoms are outlined by an amber ring with a soft glow; where a selected atom is hidden behind others, its ring shows faintly through them, so selections inside a structure remain visible.

Open \ui{Edit > Edit Structure} to work with the atom table. Use \ui{Undo} and \ui{Redo} where enabled, but retain saved checkpoints before substantial assembly or defect-generation operations. A camera reset changes only the view and does not restore a previous structure.

Ctrl+left-click adds/removes an atom from the selection. Ctrl+A selects all; Ctrl+D or Escape clears selection. Delete removes selected atoms, and right-click opens the selection context menu. Ctrl+Z undoes; Ctrl+Y or Ctrl+Shift+Z redoes. Use these shortcuts in the main workspace with no text-entry field focused.

\section{Edit Structure: atoms and cell}
The editor exposes cell vectors when a cell is present and an atom table with element and coordinate editing. \ui{Position Mode} switches between \ui{Cartesian} and \ui{Direct}. Cartesian coordinates are in \angstrom; direct coordinates are fractional lattice coefficients. Direct editing is disabled without a unit cell.

\begin{enumerate}
\item Open the source structure and save a working copy.
\item Choose \ui{Edit > Edit Structure}. Confirm the coordinate mode before typing a position.
\item Select a row to edit the desired atom. Use the element selection and \ui{Apply Element} controls for species changes.
\item Use \ui{Add Atom} to create a new row, then immediately set its element and position. The initial atom is H at the origin; leaving it there may create an overlap.
\item Inspect changed positions and atom counts in the viewport and information dialog. Save the revised structure under a descriptive name.
\end{enumerate}
Cell-vector edits define the simulation cell. Do not assume that typing a new box automatically performs the same operation as a homogeneous strain or a supercell construction. Check the resulting atom coordinates and boundary relationships. Use the integer transformation tool for deliberate periodic supercells.

\section{Transform Structure}
\ui{Edit > Transform Structure} accepts three rows of integer coefficients. It is available for a structure with a unit cell. Begin with a diagonal transformation to establish the convention: $(2,0,0)$, $(0,2,0)$, $(0,0,2)$ creates a $2\times2\times2$ periodic enlargement. For conventional FCC Cu this should contain 32 atoms when the reference contains four.

Enter the matrix, choose \ui{Apply}, and inspect the resulting lattice vectors, volume, and atom count. \ui{Cancel} discards the pending matrix. Non-diagonal matrices define combinations of lattice directions and are useful for rotated supercells. The matrix must be nonsingular; a zero determinant cannot define a three-dimensional cell. For valid integer supercells, the determinant magnitude gives the ideal volume/atom-count multiplier before additional cuts or deduplication. Verify this count rather than assuming any arbitrary matrix represents the intended orientation.

\section{Merge Structures}
\textbf{Purpose.} Assemble several structures in an interactive preview. Open \ui{Edit > Merge Structures}, load/drop the components, and select one component at a time. Its transform and gizmo controls translate or rotate that component; camera movement changes the view of the entire assembly.

\begin{enumerate}
\item Prepare and save each input independently with consistent length units.
\item Add the inputs to the merge dialog. Check each component's identity before moving it.
\item Select a component and use the visible gizmo handles to position/orient it. Inspect from at least two directions; two objects that appear separated in one projection can intersect in three dimensions.
\item Toggle \ui{Show Bounding Box} to inspect the enclosure. Use \ui{Delete Selected} to remove an unwanted component from the assembly, or \ui{Clear All} to start the assembly again.
\item Choose \ui{Merge Structures}, inspect the resulting scene, and save a new structure.
\end{enumerate}
Merging is geometric assembly. It does not find a low-strain epitaxial match, remove all close contacts, or determine a chemically correct interface termination. Inspect separations, stoichiometry, cell conventions, and periodic contacts before using the merged structure in a simulation.

\section{Cell Sculptor: supercells and cutting slabs}
\ui{Edit > Cell Sculptor} combines a periodic source, supercell repetitions, and cutting planes/slabs. Use \ui{Use Scene} to obtain the current structure or supply a source through the dialog's load/drop workflow. The source and result previews help distinguish the uncut periodic model from the generated product.

\textbf{Procedure.} Set the supercell repetitions first. Add cutting slabs, enter nonzero Miller indices, choose periodic or distance-based limits, and inspect the plane preview. At least three independent slab-normal directions are needed to close the region; Generate stays disabled for an unbounded region. Set the outside-atom opacity to make excluded atoms less prominent, then choose \ui{Generate} when the closed region contains the intended atoms. Save the resulting atomic structure only after checking which side of each boundary was retained.

In periodic slab mode, \ui{Start} identifies the starting plane and \ui{N} controls the number of structural repeats/layers along the slab normal. The displayed spacing derives from the lattice. A crystallographic repeat interval can include several chemically distinct atomic layers; do not equate \ui{N} blindly with the number of visible atomic sheets. Distance-based limits use \angstrom\ and are useful for a finite cut without an integer repeat interpretation.

For a lattice with reciprocal vectors defined without $2\pi$,
\[
\mathbf a^*\cdot\mathbf a=1,\quad
\mathbf a^*\cdot\mathbf b=\mathbf a^*\cdot\mathbf c=0,
\qquad d_{hkl}=\frac{1}{|h\mathbf a^*+k\mathbf b^*+l\mathbf c^*|}.
\]
The normal to a plane is a reciprocal-space combination. For a skew cell it is generally not the same Cartesian direction as $h\mathbf a+k\mathbf b+l\mathbf c$. Use the preview to confirm the orientation before generating a slab. Geometric cutting can create polar surfaces or nonstoichiometric terminations; choose terminations according to the intended study.

\section{Insert Dislocation}
\textbf{Purpose.} Apply a continuum-style displacement construction to a structure. Open \ui{Edit > Insert Dislocation}, use the current scene or load a reference, and use \ui{Detect Lattice} to inspect the lattice classification before choosing directions.

\textbf{Character and region.} Choose Edge, Screw, or Mixed character. Available region shapes are Half-plane, Cylinder, Sphere, Ellipsoid, and Freeform 2D. These control the construction region. They do not by themselves certify a particular relaxed dislocation-core structure or a stable physical loop.

\begin{enumerate}
\item Choose a sufficiently large reference and a fixed cell geometry.
\item Enable \ui{Auto lattice vectors} for inferred directions, or enter the slip-plane indices, Burgers direction, and line direction manually. Use crystallographically compatible, nonzero directions.
\item Locate the line using a fractional point when convenient, or the Cartesian position/offset controls. Confirm its position in the preview.
\item Set Burgers-vector scale, Poisson ratio, core radius, cutoff, and line extent. For Mixed character, set the mixed angle. Supply the selected shape's dimensions or the Freeform 2D points.
\item Choose \ui{Generate Dislocation}. Inspect RMS and maximum displacement and the displaced structure.
\item Use \ui{Replace Main Scene} to adopt the generated result, then save a new file.
\end{enumerate}
The core radius regularises the near-core field; it is a modelling parameter, not an experimentally measured core width inferred by AtomForge. The continuum approximation is least reliable near the core. Periodic boundary conditions can require compatible dislocation arrangements; an isolated displacement construction in a periodic box may create artificial long-range strain. Relax and validate with an appropriate external model.

\section{Add Interstitial Atoms and detect voids}
\textbf{Purpose.} Find geometric void candidates and place chosen atoms in selected subsets. Open \ui{Edit > Add Interstitial Atoms}, select \ui{Use Current Scene} or provide a host, and run \ui{Detect Voids}.

\textbf{Detection controls.} \ui{Grid} controls the search resolution (8--30 in the current UI); \ui{Max Voids} limits candidates. Higher resolution can find different candidates at higher cost. Use the void-type filters to include the desired coordination geometries. \ui{Select All Types} and \ui{Clear All Types} manage those filters. \ui{Show Void Polyhedra in Scene} helps relate candidate centres to their coordinating atoms.

\textbf{Placement modes.}
\begin{description}
\item[Random distribution] Choose a percentage or atom count and a seed. The percentage refers to eligible candidate sites, not automatically to the final atomic composition.
\item[Inside OBJ/STL mesh region] Load a mesh region and transform it with Translate (T), Rotate (R), and Scale (S). Inspect the mesh relative to the host; \ui{Reset Transform} restores its transform. Choose a target percentage/count among eligible sites in that region.
\item[Manual (selected voids only)] Select candidate centres in the preview and check the displayed selected-centre count. The selected subset determines placement.
\end{description}
Use \ui{Select Element} to choose the inserted species, then \ui{Apply Interstitials}. Inspect the atom-count change and nearest-neighbour separations before saving. A void is a geometric candidate, not a calculated formation-energy minimum. Site preference, charge state, local relaxation, and solubility require separate physical calculations.

\section{Structure pipeline: non-destructive editing}\label{sec:pipeline}
The other editing tools change the structure directly. \ui{Edit > Structure pipeline} edits it \emph{non-destructively}, in the spirit of OVITO: the structure becomes the \emph{input} of a pipeline, an ordered list of modifiers that each transform the result of the one before, like commands in a shell pipe. The input is kept unchanged. Changing, bypassing, reordering or deleting any modifier recomputes the output, which the view shows, so an edit made early in a long sequence never has to be redone by hand.

\paragraph{Working with the panel.} Press \ui{Start from the active structure}, or simply add a modifier: the first one starts the pipeline on the active structure. \ui{Add modifier} lists the modifiers by category and inserts the chosen one after the selected step (or at the end). The list shows the input, each step and the output on a connecting line, with the number of atoms, the number of selected atoms and the time after every step; a step that fails shows its message in red and stops the pipeline there, so the output is the data before it. Click a step to edit its parameters below the list; the output follows every change. Untick a step to bypass it without losing its settings. Every step can be moved and removed: drag it onto another step to move it there, use its up and down arrows, or select it and press \ui{Move up}, \ui{Move down}, \ui{Duplicate} or \ui{Remove} above its parameters; \ui{X} on its row removes it too, and right-clicking a step offers \ui{Move up}, \ui{Move down}, \ui{Duplicate}, \ui{Enable}/\ui{Disable} and \ui{Delete}. A step may be given a \ui{Name}, for example ``Upper half''. Untick \ui{Update automatically} to batch several edits on large structures and press \ui{Update}. \ui{Colour atoms by selection} colours the output by the current selection (1 selected, 0 not), which shows what a selection step picked. The panel is an ordinary window: move, resize or close it; the pipeline keeps working while it is closed.

Edits made with other tools while a pipeline is active change only its current output and would be replaced at the next update; the panel then warns and offers \ui{Use it as the pipeline input} or \ui{Restore the pipeline output}. \ui{Use the active structure as input} restarts the pipeline from the structure in the view. \ui{Bake} makes the output the structure (one undoable edit) and ends the pipeline; \ui{Discard} ends it and shows the input again. Pipeline updates themselves are not entered into undo history. Projects save the pipeline, its options and its unmodified input (project format 3); \ui{Save pipeline} and \ui{Load pipeline} exchange the modifier list alone as a JSON or text file, to apply the same steps to other structures.

\paragraph{Selection.} As in OVITO, many modifiers act on the \emph{selection}: selection modifiers choose atoms, and the modifiers after them (delete, assign element, displace, \ldots) act on those atoms. Every selection modifier has a \ui{Combine} mode: \emph{replace} the selection, \emph{add} to it, \emph{subtract} from it or \emph{intersect} with it, so complex selections are built from simple steps.

\paragraph{Modifiers.}
\begin{description}
\item[Selection] \code{select-element} (element list); \code{select-expression} (a condition, below); \code{select-slab} between two coordinates along x, y or z (\AA) or a, b or c (fractional, wrapped into $[0,1)$); \code{select-sphere} within a radius of a point (minimum-image distance in periodic cells); \code{select-property} in a range of the per-atom property; \code{select-random}, exactly round($fN$) atoms, reproducible for a seed; \code{expand-selection} adds the neighbours within a cutoff, repeated for a number of steps; \code{invert-selection}; \code{clear-selection}.
\item[Modification] \code{delete-selected}; \code{assign-element} to the selected (or all) atoms, e.g. for substitutions; \code{displace} by a vector; \code{random-displacement}, Gaussian with the given standard deviation per component, reproducible for a seed; \code{slice} with the plane $\hat n\cdot\mathbf r = d$: it removes the half-space above the plane, or with a width the slab $|\hat n\cdot\mathbf r - d| \le w/2$ (\ui{Invert} keeps that region instead, \ui{action select} only selects it).
\item[Cell] \code{replicate} along a, b and c; \code{supercell}, the cell of \ui{Edit > Transform Structure}: new cell vectors that are integer combinations of a, b and c (nine integers, row by row, e.g. \code{supercell "1 1 0 -1 1 0 0 0 1"}), filled with the atoms; \code{transform}, the affine map $\mathbf x' = \mathbf x M$ of atoms and, for all atoms, the cell (row vectors); \code{strain}, homogeneous normal strains and engineering shears (twice the tensor components) of atoms and cell; \code{wrap} atoms into the cell; \code{center} the atoms' extent in the cell; \code{add-vacuum}, lengthening one cell vector, optionally centring the atoms, to make slabs.
\item[Simulation] The Analysis-menu tools whose result is a structure, with the parameters of their windows: \code{relax} (\ui{Structure relaxation}), \code{nvt-dynamics} and \code{npt-dynamics} (the final frame of \ui{NVT dynamics} and \ui{NPT dynamics}) and \code{standardize-cell} (the primitive, conventional or symmetrized cell of \ui{Symmetry and Wyckoff positions}). JSON-valued inputs such as the potential are given as their JSON text, e.g. \code{relax calculator='\{"potential": "EMT"\}' fmax=0.01}. Relaxation and dynamics keep the atoms' selection and metadata.
\item[Analysis] \code{compute-property}: the Ackland--Jones structure type, centrosymmetry, coordination within a cutoff or Steinhardt $q_6$ (\S\ref{sec:defect-tools}), as the per-atom property for colouring and \code{select-property}. For example \code{compute-property centrosymmetry | select-property 0.5 100 | delete-selected} removes defect-core atoms. The Ackland--Jones method tolerates one missing neighbour, so atoms next to a single vacancy remain fcc; select those by coordination instead.
\item[Edit] \code{add-atom} at a Cartesian or fractional position; \code{set-cell}, new lattice vectors with or without scaling the atoms; \code{merge}, the atoms of another structure file at an offset; \code{insert-interstitials}, filling tetrahedral, octahedral or irregular voids (found as by \ui{Add Interstitial Atoms}) largest first or at random --- an fcc cell has one octahedral and two tetrahedral sites per atom.
\item[Build and Build \& edit] Every builder and editing tool of the Build and Edit menus is a step too, running the same code: \code{build-bulk}, \code{build-custom}, \code{build-gb}, \code{build-poly}, \code{build-nano}, \code{build-amorphous}, \code{build-interface} and \code{build-nanowire} make a structure; \code{build-surface}, \code{build-vacancy}, \code{build-sss}, \code{build-sqs}, \code{build-strain}, \code{build-primitive}, \code{build-dislocation}, \code{build-stacking-fault}, \code{build-core-shell} and \code{build-sculpt} (the Cell Sculptor) change the structure from the steps above. Their \ui{Options} are the flags of \code{AtomForge --build MODE} (Chapter~\ref{ch:api-signatures} lists them; the step's help shows them too), for example \code{build-vacancy --count 4 --seed 2} or \code{build-sss --frac "Cu=0.75,Ni=0.25"}. Steps that take a structure receive the current one; for grain boundaries, polycrystals, nanocrystals, custom structures and dislocations \ui{Use the pipeline's structure as input} chooses whether it seeds them, and for interfaces it is layer A. The structure is passed in CIF, so coordinates are kept to about $10^{-5}$ in fractional units, and the selection is cleared after these steps.
\end{description}
Grain colours, region ids and per-atom properties follow the atoms through deletions and replication.

\paragraph{Selection expressions.} \code{select-expression} selects atoms for which a condition is nonzero, for example \code{fz > 0.5 \&\& element == O} or \code{abs(x - 10) < 2 or Z == 29}. Variables: \code{x y z} (\AA), \code{fx fy fz} (fractional, 0 without a cell), \code{index} (from 0), \code{count}, \code{element} (also \code{type}), \code{Z}, \code{property} (the per-atom property, NaN when absent) and \code{selected}. Operators: \code{+ - * / \^{}} (power), \code{< <= > >= == !=}, \code{\&\& || !} (also \code{and or not}) and parentheses; functions \code{abs sqrt exp log sin cos tan floor ceil min max}; \code{pi}. Element names may be written with or without quotes; they can only be compared with \code{==} and \code{!=}.

\paragraph{Pipelines as commands.} A pipeline is also a line of text: modifier ids separated by \code{|}, each followed by its parameters in order or as \code{name=value}. Vectors take three numbers (or \code{a,b,c}), and an expression or element list takes the rest of its step; \code{||} inside an expression is the logical operator, not a pipe. \ui{Copy as command} copies the pipeline as an \code{AtomForge --pipe} command, and \ui{Edit as text} edits it in this form. The command line runs the same pipeline without the desktop:
\begin{lstlisting}[language=bash]
AtomForge --pipe "replicate 4 4 4 | select-random 0.02 seed=7 | delete-selected" --input cu.cif --output cu_vacancies.xyz
AtomForge --pipe --list
AtomForge --pipeline steps.json --input POSCAR --output out.cif --save-pipeline copy.json
\end{lstlisting}
\code{--input -} reads extended XYZ from standard input and \code{--output -} writes it (with the selection and the per-atom property as extra columns) to standard output, so AtomForge runs combine with each other and with other programs through real shell pipes; the per-step report goes to standard error (\code{--quiet} silences it):
\begin{lstlisting}[language=bash]
AtomForge --pipe "replicate 3 3 3 | select-expression 'fz > 0.5' | assign-element Ni" --input cu.cif --output - \
  | AtomForge --pipe "select-element Ni | expand-selection 2.6 | invert-selection | delete-selected" --input - --output alloy.xyz
\end{lstlisting}
A failing step stops the command with exit status 1 and names the step. \code{--report FILE} writes the per-step results as JSON, and \code{--pipe --list-json} lists every step with its parameters and its place in the menus.

\paragraph{The same features in the menus.} Every pipeline step is also a menu option, and every structure-changing Build and Edit feature is a pipeline step; the step's tooltip in the menu names it. Features with their own dialogs keep them (the builders of the Build menu, \ui{Edit Structure}, \ui{Insert Dislocation}, \ui{Add Interstitial Atoms}, \ui{Transform Structure}, \ui{Merge Structures}, \ui{Cell Sculptor} and the Analysis tools above). The others open a one-step operation window with the step's parameters: \ui{Build > Vacancies, Strained Cell, Primitive Cell, Surface Slab, Special Quasirandom Structure, Nanowire, Core-Shell Particle}; \ui{Edit > Structure Operations} (delete atoms, assign element, displace, random displacement, slice, replicate, affine transformation, strain, wrap, centre, add vacuum, compute per-atom property); and \ui{Edit > Select Atoms} (by element, expression, slab, sphere, property range, random fraction, expand, invert, clear), which sets the selection in the view and combines with it by its mode. Operations that act on atoms apply to all atoms, to the atoms selected in the view, or to the atoms where a condition holds. \ui{Apply} changes the structure as one undoable edit; \ui{Add to pipeline} appends the same step (with the condition as a select-expression step) to the structure pipeline instead.

\paragraph{Editing a step in its dialog.} Double-click a step, press \ui{Edit in dialog} above its parameters or choose it from the step's right-click menu to open the same dialog as its menu entry, filled with the step's settings: the builder of a Build step, \ui{Edit Structure} for \code{add-atom} and \code{set-cell}, \ui{Transform Structure} for \code{supercell}, the tool window for the Simulation steps, or the operation window. Dialogs that work on a structure show the one entering the step. The main button reads \ui{Update step}: it writes the dialog's settings into the step (for Build steps, as their command-line options) instead of building, and the pipeline updates its output. Loading another reference structure from a file in the dialog makes the step read that file.

\paragraph{From Python.} \code{atomforge.pipeline} builds, edits and runs the same pipelines:
\begin{lstlisting}[language=Python]
import atomforge as af
from atomforge.pipeline import Pipeline
s = af.load("cu.cif")
p = Pipeline().replicate(4, 4, 4).select_expression("fz > 0.5").assign_element("Ni")
p.add("build-vacancy", "--count 3 --seed 1")      # Build and Edit steps too
result = p.run(s)                                 # s is unchanged
print(result.structure, result.selected_count, [st["atoms"] for st in result.stages])
p.move(3, 0).disable(1).remove(2).set(0, counts=(2, 2, 2))
Pipeline.parse("replicate 2 2 2 | select-random 0.1 | delete-selected").save("steps.json")
s.pipe("add-vacuum c 15 | center")
\end{lstlisting}
Steps are methods named after the modifier (hyphens as underscores), \code{add}/\code{insert} with positional values in parameter order or keywords, or pipe text; \code{|} joins pipelines and text. \code{run} raises \code{PipelineError} naming the failing step (or with \code{check=False} returns the data before it), takes per-atom values for \code{select-property} with \code{property=}, and returns the structure, the selection, the per-atom property and the per-step results. \code{to\_text}, \code{to\_json}, \code{save} and \code{load} use the formats of the desktop and the command line. Core steps run in the native library; Build and Edit steps run through the AtomForge executable (\code{ATOMFORGE\_PATH}).

\section{Checking an edited model}
Before exporting a simulation input, check species counts, cell vectors, boundary contacts, minimum interatomic distances, and the intended periodicity. For nanoparticles and slabs, check vacuum in every relevant direction. For substitutions and defects, compare composition before and after the edit. Save both the starting model and the exact edited model used for later calculations.
