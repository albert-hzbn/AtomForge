\chapter{Projects and scientific workflows}\label{ch:workflows}
This chapter describes additions in the current source build. Rebuild the application and install the matching Python source package before using them; previously downloaded release binaries do not acquire new features automatically.

\section{Save a project and recover a session}
Use the File menu's project commands to save all open tabs in one \code{.afproject} file. A project stores atomic structures, grain colours and region IDs, camera framing, basic display switches, electronic primary and reference fields, the current mesh and result table, slice settings, and electronic operation history. It also stores the per-atom property shown with the \emph{Atom Property} colour mode (with its range and hide filters) and the scientific tools window: the selected tool, every input, and the last result with its plots, generated files and result structures, so a reopened project shows the same result without recomputing it. Inputs that refer to files store the path only; keep those files beside the project. Projects written by this version use format 2; format~1 projects from earlier releases still open. Opening a project creates tabs without replacing unrelated open work. Projects store the numerical fields themselves, so the original CHGCAR or Cube file is not required to restore the saved calculation.

Use the electronic workspace's Open/Save workspace buttons to exchange a single analysis independently. A project is not a copy of every application preference: per-element material settings, every builder's transient inputs, and running calculations are not serialized. Save important builder parameters alongside the structure. A calculation must finish or be cancelled before a project can be saved. File writes replace the destination only after successful serialization; a failed write preserves the previous project.

Enable autosave in the File menu to write a recovery project approximately once per minute while calculations are idle. The recovery command loads the latest completed snapshot. On Windows the recovery file is below \code{LOCALAPPDATA/AtomForge}; on Linux it is below \code{XDG_STATE_HOME/AtomForge}, falling back to \code{HOME/.local/state/AtomForge}. Autosave is a recovery aid, not a versioned backup system. Work after the latest successful snapshot may need to be repeated.

\section{Electronic history, cancellation and export}
Electronic Undo and Redo restore the previous numerical workspace and views. Interactive history keeps at most four snapshots and clears the undo stack for a state larger than 32 MiB; save a project before expensive operations on large grids. The history records operation selections, numeric parameters and input filenames. It does not independently establish the provenance or physical validity of an external file.

Cancel calculation requests cooperative cancellation. The current stage's progress is shown where the algorithm can measure it. The completed result is discarded if cancellation was requested. Loading and long grid loops check cancellation, although external blocking I/O and uninstrumented work may delay the response.

The Appearance quality selector offers four resolutions. It changes the displayed volume texture, ray-sampling budget and 2D sampling grid; the underlying numerical field and numerical exports retain their original resolution. Use lower quality for interaction and higher quality for a final view. Rendering quality cannot recover detail absent from the input file.

The export selector includes a 3D PNG and a 2D SVG. The PNG is rendered at 1600 by 1200 pixels using the current camera, palette and opacity. It exports the data viewport rather than the whole application dialog. The SVG preserves the current section, pan, zoom, rotation and contour display. For a rotatable downstream model export OBJ or PLY instead. Save a project to retain all loaded and derived fields together.

\section{Structural analysis and automation}
Common-neighbour and angular-distribution analysis are available from Analysis. Interface Builder and Stacking Faults are available from Build. Their C++ algorithms are also exposed through native CLI and Python workflows.
\begin{lstlisting}[language=Python]
import atomforge as af
host = af.load("POSCAR")
rows = af.cna(host, cutoff=3.1)
rdf = af.rdf(host, cutoff=6, bins=120)
adf = af.adf(host, cutoff=3.1, centre="Cu")
sro = af.sro(host, shells=3, tolerance=0.1)
voids = af.interstitial_sites(host, resolution=14, clearance=0.6)
cut = af.sculpt(host, [(1,0,0,-5,5), (0,1,0,-5,5),
                      (0,0,1,-5,5)])
\end{lstlisting}
Cutoff lengths and sculpt bounds are in Angstrom. Manual sculpt bounds are relative to the supercell centroid; periodic bounds instead specify an integer start plane and a number of structural periods. CNA is cutoff-sensitive: include the complete intended neighbour shell and use a sufficiently large periodic cell. FCC/HCP and BCC require different neighbour-shell conventions. ADF counts unordered neighbour pairs; smoothing affects the displayed values, not raw counts. These geometrical analyses do not replace energetic validation.

The native \code{--analyze} modes are cna, rdf, adf, sro, interstitial and sculpt. All require \code{--input} and \code{--output}; analyses write CSV, while sculpt writes a structure. Unsupported options are rejected. Native \code{--convert} provides structure conversion and extended XYZ export. The generated API appendix lists Python parameters and all ten builder modes, including interface and stacking-fault sequence export.

\section{Recipes and batch electronic processing}
\begin{lstlisting}[language=Python]
from atomforge.electronic import load_volume, run_pipeline, batch_process
density = load_volume("CHGCAR").fields[0]
steps = [
    {"operation":"scale", "parameters":{"factor":2}, "name":"twice"},
    {"operation":"subtract", "reference":"input", "name":"difference"},
    {"operation":"integrate", "name":"electrons"},
]
results = run_pipeline(density, steps)
report = batch_process(["density1.cube", "density2.cube"],
                       steps, "batch-results")
\end{lstlisting}
Every step names an allowlisted operation, optional parameters and an optional unique result name. A reference can identify an earlier grid or an external file. The original input remains available as \code{input}; intermediate results can be inspected before saving. Geometry and units must match for binary operations; resampling is explicit. Batch outputs use input stems, reject name collisions and existing destinations, and report each input's success or failure. Inputs named CHGCAR in different folders need distinct output names or separate batch destinations.

The Python electronic command accepts an operation, a reference, JSON parameters, a JSON recipe or batch inputs. Use its \code{--help} for current argument syntax. Recipe execution does not evaluate Python expressions. Save the recipe, source calculation settings and input hashes separately when preparing an independently reproducible study.

\section{Trajectories and animation}
Open Analysis > Trajectories and transport > Trajectory playback, choose an XYZ or extended XYZ trajectory, and use Play/Pause, First frame, the frame slider and playback speed. Frames replace the active structure; preserve the original in another tab or project first. Main-window orbit, zoom and pan remain available. The desktop reader requires species followed by Cartesian coordinates; extended XYZ properties must begin with \code{species:S:1:pos:R:3}. It reads lattice vectors from the comment and rejects incomplete frames.

Python provides broader ASE trajectory formats, including XDATCAR and LAMMPS dumps:
\begin{lstlisting}[language=Python]
from atomforge.science import read_trajectory, write_trajectory, export_animation
frames = read_trajectory("XDATCAR", format="vasp-xdatcar")
write_trajectory(frames, "trajectory.extxyz")
export_animation(frames, "trajectory.gif", fps=12, radii=0.5)
\end{lstlisting}
The desktop playback window also opens VASP XDATCAR files (including variable-cell runs that repeat the header) and LAMMPS dumps that include an \code{element} column. Opening a trajectory only indexes where each frame starts; frames are read from the file as they are shown, so trajectories far larger than memory play smoothly, and \code{AtomForge --render} streams GIF frames the same way. Other structure formats are read once and kept.

\textbf{Colour each frame} recomputes a per-atom analysis for every displayed frame and colours the atoms by it: the Ackland--Jones structure type, the centrosymmetry parameter or the Steinhardt $q_6$ bond order (each described in this chapter). The structure type chooses its own cutoff in periodic cells; the other two use the neighbour cutoff shown. The window reports the time per frame; large structures analysed every frame slow playback, so lower the frame rate or analyse selected frames with the slider. The colour range adapts to each frame; fix it in the atom-property colouring window to compare frames on one scale. \textbf{Export GIF} writes the loaded trajectory as a looping animated GIF rendered with the current camera, display settings and playback frame rate, optionally using every $N$th frame; views larger than 960 pixels are averaged down. The same is available without the window:
\begin{lstlisting}[language=bash]
AtomForge --render --input XDATCAR --output relax.gif --fps 10 --every 5
AtomForge --render --input cu.cif --output turntable.gif --frames 36 --pitch 20
\end{lstlisting}
A trajectory input gives one frame per trajectory frame; a single structure gives a turntable (default 36 frames over a full turn). Each frame has its own 256-colour palette, which is ample for rendered atoms but bands smooth gradients slightly. Python's \code{export\_animation} remains available. Python's GIF export uses fixed projection bounds across frames and explicitly chosen radii. Conversion preserves species, positions and a full cell, but the current Structure model does not retain per-axis periodicity, velocities or arbitrary per-atom trajectory properties. Keep the original trajectory for dynamics analysis.

\section{Install scientific integrations}
The following workflows live in \code{atomforge.science}; they are Python integrations rather than additional native desktop dialogs. Install the source package with its \code{science} extra to obtain ASE, pymatgen, Matplotlib and Gemmi. The native electronic library is additionally needed for stockholder integration and reciprocal-surface triangulation. External DFT, Bader and Chargemol executables and licensed calculation inputs are not bundled.

Gaussian input and Quantum ESPRESSO input conversion use ASE. A PWI export is a structural template with element-named UPF placeholders; supply real pseudopotentials and calculation parameters before running it. MOL, MOL2 and SDF conversion uses the native executable. CIFs carrying nontrivial space-group information require the crystallography extra (Gemmi) and expand symmetry-related sites. Validate disorder/partial-occupancy models separately because the Structure model represents explicit atoms.

\section{Bands, DOS, projected data and orbitals}
\begin{lstlisting}[language=Python]
from atomforge.science import read_bands, plot_bands, read_dos, plot_dos
bands = read_bands("EIGENVAL")
plot_bands(bands, "bands.svg", fermi_eV=5.2)
dos = read_dos("DOSCAR")
plot_dos(dos, "dos.png")
\end{lstlisting}
Band arrays are indexed by k point then band, separated by spin channel. Without an explicit reciprocal-path distance array, the plot labels its horizontal axis as k-point index. DOSCAR parsing checks finite data, complete blocks and consistent energy grids. Projected DOS column meanings depend on the producer's spin and LORBIT settings; pass \code{projected_labels} when these are known rather than inferring orbital labels from an ambiguous column count.

\code{read_projections("PROCAR")} returns pymatgen's projection object. Select and sum the intended ion/orbital channels to construct nonnegative weights matching the band arrays, then pass these to \code{plot_bands(..., projections=weights)} for fat bands. Spin-orbit projections require the conventions of the supplied PROCAR. Compare the number and ordering of k points and bands before combining files.

\code{orbital_density(wavecar,poscar,output,kpoint=0,band=0)} reconstructs a selected orbital and writes PARCHG for the desktop electronic viewer. Indices are zero-based; spin, spinor and FFT scale are explicit options. This is a plane-wave reconstruction through pymatgen and excludes PAW augmentation; it is not an all-electron density or an exact total-energy calculation.

\section{Reciprocal-space surfaces}
\begin{lstlisting}[language=Python]
from atomforge.science import read_bandgrid, plot_surface
bands = read_bandgrid("bands.bxsf", energy_unit="eV", reciprocal_unit="1/A")
label = next(iter(bands.bands))
plot_surface(bands, label, "fermi-surface.png")
bands.surface(label).save("fermi-surface.obj")
\end{lstlisting}
BXSF BANDGRID data are read in z-fastest order and preserve endpoint samples. The default isosurface level is the file's Fermi energy; out-of-range levels are rejected. Supply the producing program's actual units. The resulting surface spans the reciprocal parallelepiped and is not folded into the first Brillouin zone. Keep it separate from real-space charge grids. Raw BXSF input is intentionally not passed to the desktop real-space density loader.

\section{Charge partitioning}
\code{hirshfeld(density, proatoms)} applies stockholder weights to an electron-density grid using caller-supplied neutral-proatom grids. All geometries and density units must agree. Proatoms must cover every nonzero density sample. The electron populations sum to the integrated density; optional reference electron counts produce net atomic charges. Use compatible valence or all-electron conventions throughout. AtomForge does not invent atomic reference densities from Gaussian functions.

\code{bader(path, reference=..., potcar=..., executable=...)} runs the actual Henkelman solver through pymatgen. A summed AECCAR0+AECCAR2 reference can define basins while CHGCAR supplies the integrated valence charge. Returned raw populations count electrons; when POTCAR is provided, net charge is reference valence count minus population. Inspect vacuum charge and total electron count as convergence checks. Cube input requires the explicit cube format option.

\code{ddec(directory, atomic_densities=...)} uses Chargemol DDEC6/CM5. It requires the actual solver, atomic-density database and required VASP files. Set \code{run=False} to parse existing results. Errors are reported directly; neither Bader nor DDEC falls back to a Voronoi partition. Backend availability and numerical convergence are separate from successful import of the Python wrapper.

\section{Diffraction, relaxation, dynamics and phonons}
\code{powder_diffraction(structure)} uses pymatgen's X-ray or neutron calculator with explicit wavelength and angle limits. The result contains peak angles, intensities and reflection information; \code{plot_diffraction} produces a broadened pattern. \code{single_crystal} uses explicitly supplied per-site, per-reflection complex scattering factors. Include any intended occupancy and displacement attenuation in those effective factors. Radiation, isotope and form-factor assumptions affect intensities and should be recorded.

\begin{lstlisting}[language=Python]
from ase.calculators.emt import EMT
from atomforge.science import relax, molecular_dynamics, phonons, mode_frames
result = relax(host, EMT(), fmax=0.02, steps=200)
print(result.converged, result.energy)
motion = molecular_dynamics(host, EMT(), steps=100,
                            timestep_fs=1, temperature_K=300, seed=7)
modes = phonons(host, EMT(), [[0,0,0]], directory="fresh-phonon-cache",
                supercell=(2,2,2), displacement=0.01)
animation = mode_frames(host, modes["modes"][0,0])
\end{lstlisting}
EMT is an example potential with limited element support, not a general DFT model. A caller-configured ASE calculator can instead connect an external DFT or interatomic-potential engine. Its executable, pseudopotentials, settings and convergence remain the caller's responsibility. BFGS returns a convergence flag; reaching the step limit does not establish equilibrium. Cell relaxation requires a periodic structure and stress-capable calculator.

Dynamics uses NVE velocity-Verlet. Temperature sets the initial velocity distribution, not a thermostat. Check total-energy drift and timestep convergence. Phonons use finite displacements in a fresh cache directory; q points are fractional reciprocal coordinates, energies are in eV, and negative values denote imaginary frequencies. Check supercell and displacement convergence. \code{mode_frames} animates a supplied Gamma-point mode with an explicit maximum displacement amplitude. A geometric builder or a rendered vibration does not by itself establish dynamical stability.

\section{Condensed-matter tools: desktop, Python and command line}
The Analysis menu groups tools by task: \textbf{Structure and defects}, \textbf{Trajectories and transport}, \textbf{Electronic structure}, \textbf{Reciprocal space}, \textbf{Thermal and mechanical}, and \textbf{Simulation}. Existing tools are alongside related analyses: CNA, RDF, ADF and SRO appear with structural analyses; trajectory playback appears with transport analyses; electronic post-processing, Wannier and LOBSTER appear with electronic analyses. AtomForge computes the tools below natively; the twenty shared with \code{atomforge.science} are joined by native structure relaxation. The desktop dialog and the \code{AtomForge --science} command share one C++ implementation and need no Python installation. Parameter names, units and conventions match \code{atomforge.science}, which provides the same analyses to Python scripts through NumPy, SciPy and ASE. Simulation tools use the built-in EMT and Lennard-Jones potentials or an EAM/Finnis--Sinclair potential file. Symmetry paths use the spglib library included with AtomForge.

Choose a tool from its task section. Each family of tools opens its own window, arranged for that kind of work:
\begin{itemize}
\item \textbf{Atom analysis} (structure type, symmetry and Wyckoff positions, dislocation lines, clusters, voids, centrosymmetry, bond order, Wigner--Seitz defects, local strain): a narrow panel to keep beside the viewport. \textbf{Analyse the active structure} is on by default and supplies the positions, cell and periodicity, so only the settings remain; turn it off to choose a file. \textbf{Analyse} runs the tool and colours the atoms by the first per-atom result straight away (turn off \textbf{Colour automatically after each analysis} to keep the current colouring); the radio buttons switch between properties.
\item \textbf{Trajectory analysis} (MSD, diffusion, VACF, vibrational spectrum, structure factor, trajectory-averaged g(r), coordination and bond angles): the trajectory source across the top, naming the frames loaded in Trajectory playback, the settings in one row and a wide plot below.
\item \textbf{Property calculator} (band gap, effective mass, work function, equation of state, elastic tensor, harmonic thermodynamics, and the potential-driven elastic constants, equation-of-state scan, point-defect formation and planar-defect energies): the inputs on the left; the computed quantities on the right as large values, with tensors such as the stiffness matrix shown as tables.
\item \textbf{Plot workspace} (VASP bands and DOS, phonon DOS, powder XRD, electron diffraction, reciprocal path): a settings sidebar beside a large plot; several plots appear as tabs above it.
\item \textbf{Simulation run} (relaxation, NVT, NPT, NEB, phonons): numbered steps for the system, the interatomic potential and the protocol, with rarely changed settings under \textbf{Advanced options}; the run bar shows progress, and the run summary appears beside its plots.
\item \textbf{Input generator} (band-structure inputs, LAMMPS export): a compact form and a browser of the generated files with a preview, \textbf{Save this file}, \textbf{Save all files} and \textbf{Copy to clipboard}.
\end{itemize}
The windows show a one-line description of each tool; its method, units, assumptions and limits are described in the tool lists of this section and in \S\ref{sec:defect-tools}--\ref{sec:automation-tools}. Fill the grouped form. Optional inputs expand when their checkbox is enabled; Boolean settings use one checkbox. Periodic boundaries have separate a, b and c checkboxes. Fit and vacuum intervals use Start/End fields; the spectrum window uses a choice list. Select \textbf{Load from file} and \textbf{Browse} for numerical CSV, NPY, JSON or structure/trajectory files, or select \textbf{Enter values} for small JSON arrays. Expand \textbf{File options} to select a zero-based column or a dotted JSON field such as \code{result.msd_A2}. Numeric CSV files have no header; matrix inputs use the whole table. Only data are read; array strings are not evaluated as Python code. The forms scroll on smaller windows while the run button stays visible.

Structure inputs in simulation tools offer \textbf{Use active structure}. The application copies the current structure into the calculation request without modifying the active tab. Position inputs of the local analyses offer the same button; for a periodic structure it also fills the matching cell input and enables all three periodic axes. Cell inputs offer \textbf{Use active cell}. When a trajectory is open in Trajectory playback, the positions or velocities inputs of MSD, velocity autocorrelation, the vibrational spectrum and the structure factor offer \textbf{Use loaded trajectory}; the file is read again by the analysis, so its velocities and \code{time_fs} metadata are used. Structure files with multiple frames supply trajectory positions. Atom ordering must remain consistent. Velocity analysis requires explicit velocity data in Angstrom/fs or an extended XYZ trajectory with ASE-style \code{momenta} or Angstrom/fs \code{velocities} columns; positions alone do not supply velocities.

AtomForge reads data from JSON, NPY, numerical CSV/TXT/DAT tables, VASP EIGENVAL, XYZ/extended XYZ, POSCAR/CONTCAR, XDATCAR and LAMMPS dump files. Other structure formats supported by the file browser provide a single structure. Compressed EIGENVAL files (gzip, bzip2 and xz) are supported. XDATCAR import accepts repeated cell headers. For trajectory files, velocity, mass and cell inputs select the corresponding property automatically. Numeric column selection works for CSV, NPY and JSON tables; invalid columns are rejected. When a trajectory contains \code{time_fs} metadata, its intervals must be uniform and match the requested sampling interval. A simulation's final partial interval must be trimmed or resampled before time-correlation analysis. Simulation structures with a cell are periodic along all three axes; structures without a cell, including nonperiodic bounding boxes, remain nonperiodic.

Press the window's run button (\textbf{Analyse}, \textbf{Analyse trajectory}, \textbf{Calculate}, \textbf{Compute}, \textbf{Run simulation} or \textbf{Generate files}). The calculation runs in the background, so you can keep working with the structure. A progress bar appears when the fraction completed can be estimated. \textbf{Cancel} stops the calculation at its next checkpoint. The result area lists scalar results with their units and shows small tensors as tables; \textbf{Full report} adds summary ranges for large arrays; \textbf{Save results} uses the shared file browser to export full JSON arrays, validity masks, structural frames and the original request parameters. For NEB, NVT, NPT and reciprocal paths, \textbf{Save structures} exports extended XYZ and \textbf{Open final structure in a new tab} brings the last frame or primitive structure into the viewport. Saved trajectories can be opened in Trajectory playback. Invalid local environments are represented by null in JSON, with a separate validity mask. Large arrays are not fully printed in the summary. The result area plots the returned curves: MSD with its Cartesian components, the diffusion fit, VACF, vibrational spectra, the structure factor, equation-of-state data with the fitted curve, phonon DOS, harmonic thermodynamics, the relaxation energy and force history (logarithmic), the NEB energy along the cumulative image distance, and dynamics temperature, energy, volume and pressure. Per-atom results (centrosymmetry, $D^2_{\min}$, von Mises shear and volumetric strain, $q_l$, coordination and Wigner--Seitz distances) appear as histograms. Hover a plot for values; \textbf{Export plot data} writes the plotted series as CSV.

\textbf{Keep for comparison} stores the current result of a tool. Change inputs and run again: the plots then overlay the kept runs on the same axes (series named \emph{Run 1:}, \emph{Run 2:}, \ldots, \emph{Current:}; turn this off with the overlay checkbox), \textbf{Export plot data} writes the overlaid series, and \textbf{Compare with kept runs} lists the scalar results of every run side by side. Kept runs are cleared when another tool is chosen; save results that must be kept permanently.

Per-atom results can also colour the structure. Atom analyses colour the view automatically; for other results, or to switch property, choose it and press \textbf{Colour atoms in the view}. Colouring is available when the result has as many atoms as the active structure. The view switches to \ui{View > View Structure By > Atom Property} with a viridis colour bar. The \ui{Atom property colouring} window sets an automatic or manual range and can hide atoms outside the range or without a valid value; for example, hide atoms with centrosymmetry below 0.5\,\AA$^2$ to show only defect cores. Invalid environments are grey. Deleting atoms keeps the property aligned; the view returns to element colours when the property no longer matches the atoms. Temporary calculation files are retained under the system temporary directory's \code{AtomForge-science} folder; save results needed for a permanent record.

\subsection{Trajectory and local-structure analyses (priorities 1--9)}
\begin{enumerate}
\item \textbf{Mean-square displacement (MSD).} Load positions shaped as frames by atoms by three coordinates, and set the sampling interval in fs. Prefer unwrapped coordinates. If wrapped is enabled, supply a fixed cell; the inter-frame motion must be small enough to resolve the shortest periodic displacement. Run and inspect the lag-time MSD and Cartesian displacement tensor. The MSD is averaged over all time origins, $\mathrm{MSD}(\tau)=\langle|\mathbf r_i(t+\tau)-\mathbf r_i(t)|^2\rangle_{i,t}$, and the displacement tensor is $\langle\Delta r_a\Delta r_b\rangle$, a second moment rather than a covariance about the mean displacement. Atom order must be the same in every frame. Optional geometric-centroid drift removal is not mass-weighted centre-of-mass removal. A changing cell requires a physically chosen reference-frame transformation before this analysis.
\item \textbf{Diffusion coefficient.} Supply the MSD lag times and values, then explicitly select a diffusive fit interval. Set dimensions to the number of directions summed in that MSD. The result uses $D=\mathrm{slope}/(2d)$ and reports both Angstrom$^2$/fs and m$^2$/s, intercept and $R^2$. Check several fit intervals and independent trajectories. The ordinary least-squares standard error is a fit diagnostic, not a confidence interval accounting for correlated time origins.
\item \textbf{Velocity autocorrelation.} Supply velocities in Angstrom/fs and the frame interval. The result averages $\mathbf v(t)\cdot\mathbf v(t+\tau)$ over atoms and time origins. The average is unbiased: each lag is divided by its own number of time origins. Without normalization the unit is \AA$^2$/fs$^2$; optional normalization sets the zero-lag value to one, and zero-velocity data cannot be normalized. Drift removal subtracts each frame's geometric mean velocity, not the mass-weighted centre-of-mass velocity. Truncate the lag range before poorly sampled tails dominate interpretation.
\item \textbf{Trajectory vibrational spectrum.} Load velocities, choose a Hann or rectangular window, and optionally supply atomic masses. The one-sided velocity periodogram, the Fourier partner of the velocity autocorrelation, is normalized to unit integrated spectral weight per THz. Resolution and the Nyquist frequency follow from the trajectory duration and sampling interval; zero padding adds no information. Inspect its reported resolution and Nyquist frequency. This classical velocity spectrum is not an IR, Raman or quantum neutron-scattering intensity.
\item \textbf{Local strain and $D^2_{\min}$.} Load corresponding reference and current coordinates, choose a reference neighbor cutoff, and supply cells and periodic axes. Neighbours are selected in the reference structure, and atoms must correspond by order. The tool fits the local deformation gradient $\mathbf F$ by least squares, minimising $\sum_j|\mathbf d_j-\mathbf F\mathbf d^0_j|^2$ over the neighbour vectors, and reports the Green--Lagrange strain $\tfrac12(\mathbf F^\mathsf T\mathbf F-\mathbf I)$ and $D^2_{\min}$, the \emph{sum} (not mean) of the squared non-affine residuals in \AA$^2$. Known box deformation is retained. Three-dimensional rank-deficient neighborhoods are marked invalid; a planar neighborhood does not define a full 3D strain tensor.
\item \textbf{Centrosymmetry parameter.} Choose an even neighbor count, commonly twelve for FCC or eight for BCC, and a cutoff containing those neighbors. The conventional Kelchner construction sums the smallest $N/2$ squared pair-vector sums among the nearest $N$ neighbors. Among the nearest $N$ neighbours within the cutoff (periodic images included), all distinct pairs are formed and the $N/2$ smallest $|\mathbf r_i+\mathbf r_j|^2$ are summed; this is the conventional smallest-pair algorithm, not an optimal disjoint matching. Perfect centrosymmetric environments approach zero. Missing neighbors are invalid, not zero; a nonzero value alone does not identify a unique defect type.
\item \textbf{Steinhardt bond order.} Select angular degrees, typically four and six, a cutoff, cell and periodic axes. The tool returns the rotationally invariant local $q_l=\sqrt{\tfrac{4\pi}{2l+1}\sum_{m=-l}^{l}|\bar Y_{lm}|^2}$, where $\bar Y_{lm}$ is the equal-weight average of $Y_{lm}(\hat{\mathbf r}_{ij})$ over the bonds of atom $i$; atoms without neighbours are invalid. For an ideal FCC first-neighbor shell, $q_4\simeq0.190941$ and $q_6\simeq0.574524$. These are local $q_l$, not neighbor-averaged $\bar q_l$ or third-order $w_l$ invariants.
\item \textbf{Wigner--Seitz defects.} Load reference sites and current atom positions. Supply the reference cell and, if needed, a deformed current cell to remove homogeneous box strain. Each atom is assigned to its nearest reference site (with the current cell mapped back to the reference cell); inspect site occupancies, vacant sites and sites with more than one occupant. An occupancy $n>1$ contributes $n-1$ excess interstitial atoms. Equidistant assignments are flagged; the tool does not uniquely label which atom in a multiply occupied site is the interstitial.
\item \textbf{Static structure factor.} Supply one structure or a trajectory and Cartesian wave vectors in radians/Angstrom, including the reciprocal $2\pi$ factor. Optional scattering amplitudes weight atoms. The normalization is $S(\mathbf q)=\langle|\sum_jb_j e^{i\mathbf q\cdot\mathbf r_j}|^2\rangle/\sum_j|b_j|^2$; equal weights give $S(0)=N$. Use commensurate reciprocal points for wrapped periodic coordinates. No powder averaging or forward-scattering subtraction is implied.
\end{enumerate}

\subsection{Electronic and thermomechanical analyses (priorities 10--16)}
\begin{enumerate}\setcounter{enumi}{9}
\item \textbf{Band gap and band edges.} Load an EIGENVAL file or an energy array shaped as k points by bands, optionally preceded by a spin dimension. Supply the Fermi energy separately in the same energy reference. Inspect the fundamental sampled gap, smallest same-spin direct gap and extremum indices. A band crossing $E_F$ on the supplied mesh, or a sampled state within the tolerance of $E_F$, marks a metal. Smearing occupations are not interpreted. A sparse k mesh can miss pockets or extrema, and the direct gap is not an optical excitation energy.
\item \textbf{Effective-mass tensor.} Supply at least ten independent points in a small three-dimensional Cartesian k neighborhood, one consistently tracked band's energies, and the expansion centre. The band is fitted by the quadratic model $E=E_0+\mathbf g\cdot\delta\mathbf k+\tfrac12\delta\mathbf k\cdot\mathbf H\cdot\delta\mathbf k$ with $\mathbf k$ a Cartesian wave vector in rad/\AA{} (not a fractional position or path length); the mass tensor is $\hbar^2\mathbf H^{-1}$. Inspect signed principal masses in electron-mass units, principal axes, the residual band gradient $\mathbf g$ (which should be small at an extremum) and fit error. A one-dimensional plotted band path is insufficient for the full tensor. Negative electron curvature corresponds to positive hole mass after sign reversal.
\item \textbf{Work function.} First obtain a planar electron potential-energy profile, for example using the electronic workspace's planar averaging. Supply distances, potential values, Fermi energy and a vacuum interval. The result is $\Phi=\langle V\rangle_{\mathrm{vac}}-E_F$, the mean potential over the selected interval minus the Fermi energy; the vacuum region is not detected automatically. For VASP use the electrostatic LOCPOT channel with a consistent reference. Inspect the slope/flatness flag and vacuum spread. Evaluate opposite slab faces separately; dipole corrections are not introduced by this analysis.
\item \textbf{Equation of state.} Supply at least five distinct positive volumes and consistent total energies bracketing a minimum. A third-order Birch--Murnaghan fit reports equilibrium volume, energy, bulk modulus in GPa, pressure derivative and residuals. The reported parameter covariance is a numerical fit diagnostic, not an estimate of model or convergence error; compare residuals and vary the fitted volume range. Energies and volumes must refer to the same cell or atom-count normalization.
\item \textbf{Elastic tensor and moduli.} Supply independently varied small strains and the corresponding stresses in GPa. Engineering-Voigt order is xx, yy, zz, yz, xz, xy; shear strains are twice tensor shear, while shear stresses are not doubled. Stress is positive in tension. The least-squares fit $\boldsymbol\sigma=\boldsymbol\sigma_0+\mathbf C\boldsymbol\epsilon$ includes the prestress $\boldsymbol\sigma_0$ and needs a full-rank strain design (at least seven samples); it symmetrizes the stiffness, and reports mismatch, residuals, zero-prestress stability and Voigt--Reuss--Hill moduli where stable. Check strain-amplitude convergence; the stability test does not substitute for finite-pressure stability criteria.
\item \textbf{Phonon band structure and DOS.} Select a relaxed periodic structure and a potential. AtomForge displaces every atom of the unit cell by $\pm$\textbf{Finite displacement} in a supercell at least \textbf{Minimum supercell width} wide (or explicit \textbf{Supercell repetitions}) and differences the forces into harmonic force constants. The acoustic sum rule is enforced, and the dynamical matrix shares force constants between equidistant periodic images, as phonopy does, so q points between supercell vectors are interpolated. With \textbf{Use the symmetry band path}, phonons are computed in the standardized primitive cell along its HPKOT path and plotted with labelled special points; otherwise supply explicit fractional q points. A Gamma-centred mesh gives the DOS (normalised to three modes per atom) and harmonic thermodynamics, which are omitted when the mesh has imaginary modes. Frequencies are in THz, negative for imaginary modes. Converge the supercell width and check that acoustic branches vanish at $\Gamma$; imaginary frequencies indicate an unrelaxed structure or an instability with the chosen potential.
\item \textbf{Phonon density of states.} Supply mode energies in eV shaped as q points by branches, a plotting grid, Gaussian width and optional q-point weights. The analytic total weight is the number of branches per cell. Inspect the enclosed plotted weight to detect truncated tails. Negative imaginary-mode energies remain on the negative axis; broadening does not make them stable.
\item \textbf{Harmonic thermodynamics.} Supply a converged mode mesh, normalized or unnormalized nonnegative q weights and a temperature list. Results include zero-point energy, Helmholtz free energy, internal energy, entropy and constant-volume heat capacity, in eV per cell and eV/(cell K), not per mole. Modes within $\pm$ the zero tolerance (such as the acoustic modes at $\Gamma$) are omitted. At zero temperature, free/internal energies equal the zero-point energy. Imaginary modes beyond tolerance are rejected; omitted near-zero mode weight is reported. Electronic, configurational, thermal-expansion and anharmonic contributions are absent.
\end{enumerate}

\subsection{Simulation and reciprocal-space workflows (priorities 17--20)}
\begin{enumerate}\setcounter{enumi}{16}
\item \textbf{Structure relaxation.} Select a structure and a potential, a force tolerance and a step limit. FIRE minimises the energy with respect to atomic positions. With \textbf{Relax the cell shape and volume}, the full cell also relaxes at the target pressure (positive in compression) by minimising the enthalpy $E+PV$; cell forces are scaled by the atom count, as in ASE's \code{UnitCellFilter}. The result reports convergence, the energy change, the residual stress and pressure, the final cell and the relaxed structure, which \textbf{Open final structure in a new tab} loads. Use relaxed endpoints for NEB and relaxed cells before elastic or equation-of-state sampling. A converged relaxation finds a local minimum, not necessarily the ground state.
\item \textbf{NEB migration path.} Select initial and final structures with the same ordered species and fixed cell. Enable \textbf{Relax both endpoints first} to minimise them at fixed cell before the band is built; the result reports whether each endpoint converged. Set the number of images to 0 to choose it automatically from the total endpoint displacement (one image per \textbf{Automatic image spacing}, between 5 and 31 images). To continue an unconverged run, save its structures and supply the file as \textbf{Restart from saved images}; the saved images (including endpoints) replace the interpolation, so initial and final structures are then optional. Choose an interatomic potential, image count, spring constant, force tolerance and iteration limit. The tool performs improved-tangent NEB with optional climbing image and shortest-image interpolation, optimised with FIRE. Inspect convergence, endpoint forces and both sampled barriers. Each image evaluates its own instance of the potential. Endpoint relaxation remains the user's responsibility.
\item \textbf{NVT dynamics.} Select a structure, an interatomic potential, temperature, timestep and thermostat relaxation time. Langevin dynamics (BAOAB splitting) returns frames, physical energies, temperatures and velocities. \textbf{NVE production steps} continue after the thermostatted run with energy-conserving velocity Verlet (at the final cell for NPT); the plots mark where production starts and the result reports the total-energy drift per atom per picosecond, a direct check of the timestep. Results include block-averaged statistics for temperature and total energy (and volume and pressure for NPT): mean, standard deviation and the standard error from five contiguous blocks, which accounts for correlation between samples. Statistics use the production samples when present, otherwise the samples after \textbf{Exclude samples before}. A standard error that changes strongly with the block count, or a drifting block mean, means the run is too short. The seed controls reproducibility of initialization and thermostat noise. The centre of mass is not constrained; remove unwanted drift during analysis. Equilibrate before collecting statistics; thermostatting does not establish equilibration or conserve the physical energy.
\item \textbf{NPT dynamics.} Select a fully periodic structure, an interatomic potential, temperature, pressure in GPa and thermostat/barostat times. EMT, Lennard-Jones and EAM all supply the required stress. The isotropic Martyna--Tobias--Klein integrator with Nos\'e--Hoover chains changes cell volume while keeping shape fixed. Positive target pressure is compression. Inspect temperature, pressure and volume histories and convergence with timestep; instantaneous fluctuations should not be mistaken for failure to match the target.
\item \textbf{Symmetry reciprocal-space path.} Select a periodic structure, a reciprocal sampling spacing and symmetry tolerance. AtomForge finds the space group with spglib and builds the HPKOT path from SeeK-path's published tables and conventions. It returns the standardized primitive structure, reciprocal basis, labels and explicit disconnected segments. Use its returned primitive cell when interpreting fractional k points; input supercell fractions are generally different. The time-reversal switch controls path completion, not magnetic-space-group analysis.
\end{enumerate}

\subsection{Defect identification, clusters and diffraction}\label{sec:defect-tools}
These native tools have no \code{atomforge.science} counterpart; run them from the desktop or with \code{AtomForge --science}.
\begin{itemize}
\item \textbf{Structure type (Ackland--Jones).} Classifies every atom as fcc, hcp, bcc, icosahedral or other from the bond angles of its neighbours (Ackland and Jones, Phys. Rev. B 73, 054104 (2006)). The six nearest neighbours define a local length scale $r_0$; the cosines of the angles between bonds within $\sqrt{1.45}\,r_0$ are binned and the histogram is compared with those of the ideal lattices. Because $r_0$ is local, the classification tolerates thermal vibration (an fcc crystal with 0.07\,\AA{} random displacements remains over 95\% fcc). With a cell the cutoff is automatic (three Wigner--Seitz radii, beyond the second bcc shell); open structures need an explicit cutoff. Surface, grain-boundary and core atoms are \emph{other}; stacking faults in fcc appear as hcp layers. Colour the atoms by type, or use the type as a mask for cluster analysis.
\item \textbf{Dislocation lines and Burgers vectors.} Compares a deformed structure with its perfect reference (same atoms, same order), in the spirit of the dislocation extraction algorithm. Atoms whose structure type changed form the cores; slip by a full lattice vector leaves atoms crystalline, and free surfaces are excluded because they are already non-crystalline in the reference. Cores are clustered into lines. The line direction is the lattice period of a line that wraps the cell, otherwise the principal axis of its core. The Burgers vector is the closure failure of a right-handed circuit around the line through the reference atoms, with every displacement step reduced modulo the nearest-neighbour lattice vectors, so it is an exact lattice vector (for example $a/2\langle110\rangle$ with length 2.553\,\AA{} in Cu). The result lists each line's atoms, direction, Burgers vector, character angle (0$^\circ$ screw, 90$^\circ$ edge), centroid, length and a polyline; core clusters whose circuit closes are counted as non-dislocation defects. Lines closer than about twice their core radius, or strongly curved loops, need an explicit smaller circuit radius. Partial dislocations bounding a stacking fault are reported as one dissociated core.
\item \textbf{Atom clusters.} Groups atoms closer than a bond cutoff into connected clusters through periodic boundaries, optionally restricted by a per-atom mask (nonzero selects; for example non-crystalline atoms, or one species). Each cluster reports its size, unwrapped centroid, radius of gyration and whether it percolates through the periodic cell.
\item \textbf{Voids and empty space.} Grid points farther than atomic radius plus probe radius from every atom are empty; connected empty points form voids, wrapped through periodic boundaries, while regions reaching an open boundary are treated as the exterior. The default atomic radius is half the nearest-neighbour distance. With the default 1\,\AA{} probe, a perfect fcc metal has no voids (its octahedral holes have a free radius of only 0.146$a$), a vacancy is one void lined by its 12 neighbours, and two adjacent vacancies remain two probe-accessible regions because the channel between them is as narrow as an octahedral hole; a smaller probe connects them. Each void reports the volume accessible to probe centres, an equivalent radius and a pore-radius estimate (equivalent radius plus atomic and probe radii).
\item \textbf{Powder X-ray diffraction.} Kinematic structure factors from four-Gaussian atomic scattering factors (the coefficients used by pymatgen), an optional isotropic Debye--Waller factor $\exp(-Bs^2)$ and the Lorentz-polarization factor $(1+\cos^22\theta)/(\sin^2\theta\cos\theta)$. Every reflection inside the limiting sphere is summed, so multiplicities and systematic absences follow automatically; peaks are scaled to 100, labelled with a representative $(hkl)$ and broadened with a Gaussian of the chosen FWHM. The default wavelength is Cu~K$\alpha$ (1.54184\,\AA); use 0.71073\,\AA{} for Mo~K$\alpha$. Anomalous dispersion, preferred orientation, absorption and instrument profiles are not modelled.
\item \textbf{Electron diffraction (zone axis).} Lists the reflections $\mathbf g=h\mathbf b_1+k\mathbf b_2+l\mathbf b_3$ of the zero-order Laue zone of $[uvw]$ ($hu+kv+lw=0$) within $|g|_{\max}$, with intensities $|F|^2$ scaled to 100, with detector coordinates in \AA$^{-1}$, scattering angles in mrad for the relativistic wavelength of the chosen voltage (0.02508\,\AA{} at 200\,kV), and intensities from Mott--Bethe electron scattering factors. The pattern is kinematic: dynamical effects such as double diffraction into forbidden reflections, excitation errors and higher-order Laue zones are not included.
\end{itemize}

\subsection{Electronic-structure output and DFT inputs}
\begin{itemize}
\item \textbf{VASP band structure, DOS and fat bands.} Select the \code{EIGENVAL} file and, optionally, a line-mode \code{KPOINTS} file, the \code{POSCAR} or \code{CONTCAR}, \code{DOSCAR} and \code{PROCAR}. The KPOINTS labels mark the high-symmetry points; where consecutive segments do not join, the break is drawn at one distance with a combined label such as \code{M|R}. With the structure, distances are Cartesian in \AA$^{-1}$ with $2\pi$ included (the same convention as the reciprocal-path tool) and element names are available; otherwise distances are in fractional reciprocal coordinates. The Fermi energy comes from the input field, else from DOSCAR, and all energies are shown relative to it, with the band gap computed from the sampled bands. DOSCAR adds the total DOS (both spins) and, when it contains site projections, the DOS summed per element. PROCAR adds fat-band weights: the fraction of each state's projection on an element and orbital (\code{s}, \code{p}, \code{d}, \code{f}, an $lm$ name such as \code{dxy}, or \code{all}); the fat-band plot highlights states with more than 30\% of that character. Compressed files are read directly. Projections are only as complete as the VASP projection spheres; weights compare character between states rather than giving absolute charges.
\item \textbf{Band-structure inputs (VASP, Quantum ESPRESSO).} Generates inputs on the HPKOT path of the structure: a line-mode \code{KPOINTS} file and the standardized primitive \code{POSCAR} for VASP, and \code{CELL_PARAMETERS}, \code{ATOMIC_SPECIES} (pseudopotential names are placeholders), \code{ATOMIC_POSITIONS} and \code{K_POINTS crystal\_b} cards for Quantum ESPRESSO, where each point's weight is the number of steps to the next point (1 marks a jump). Save them with \textbf{Save generated files}, or write them with \code{AtomForge --science dft-inputs \ldots{} --files DIR}. Use the generated primitive cell for the self-consistent calculation too, so the path coordinates refer to the same reciprocal basis.
\end{itemize}

\subsection{Symmetry, mechanical properties and defect energies}\label{sec:property-workflows}
These tools take a structure and, except symmetry, an interatomic potential, and run the calculations themselves.
\begin{itemize}
\item \textbf{Symmetry and Wyckoff positions.} Finds the space group of a periodic structure with spglib: number, Hermann--Mauguin and Hall symbols, point group, crystal system and all operations, and for each atom its Wyckoff letter, site symmetry and symmetry-equivalent orbit (one row per orbit lists element, Wyckoff position, multiplicity and site symmetry). It produces three cells: the idealized conventional and primitive standard cells, and the input cell with symmetrized positions, in which each atom is the average of its images under the operations (the largest shift is reported). \textbf{Cell to open} chooses which one \textbf{Open final structure in a new tab} loads. The tolerance $\mathrm{symprec}$ (default $10^{-3}$\,\AA) is how far atoms may deviate from exact symmetry: a relaxed or noisy structure may need a larger value to show its intended space group, and the symmetrized cell then has that symmetry exactly. Colour atoms by orbit or Wyckoff position to see equivalent sites.
\item \textbf{Elastic constants (strain and relax).} Applies each of the six engineering-Voigt strains (xx, yy, zz, yz, xz, xy; shears are $2\epsilon_{ij}$) at $\pm$ every amplitude up to the largest strain (default 1\%, two amplitudes per sign), relaxes the ions at each fixed strained cell and fits $\boldsymbol\sigma = \boldsymbol\sigma_0 + \mathbf C\boldsymbol\epsilon$ with the elastic-tensor tool: the stiffness matrix, Voigt--Reuss--Hill moduli and the stability test. Internal relaxation is essential for lattices with more than one atom per primitive cell: for Stillinger--Weber silicon it lowers $C_{44}$ from about 117 to 56.4\,GPa, while $C_{11}=151.4$ and $C_{12}=76.4$\,GPa. Relax the structure with its cell first; a remaining prestress is reported, not removed. Converge the largest strain: too small amplifies force-tolerance noise, too large adds anharmonicity.
\item \textbf{Equation of state (volume scan).} Scales the cell isotropically from $(1-\Delta)$ to $(1+\Delta)$ of its volume ($\Delta$ = volume range, default 0.1) at the chosen number of volumes, relaxes the ions at each and fits the third-order Birch--Murnaghan equation of state: equilibrium volume and energy, bulk modulus and its pressure derivative, with the pressure from the stress at each volume. The bulk modulus agrees with $(C_{11}+2C_{12})/3$ from the elastic constants of a cubic crystal. Keep the range near the minimum; fit residuals show when it is too wide.
\item \textbf{Point-defect formation energy.} For a vacancy, interstitial or substitution in a supercell, $E_f = E_\mathrm{defect} - E_\mathrm{bulk} - \sum_i \Delta n_i \mu_i$, where both supercells are relaxed (ions, and optionally the shape and volume of the defect cell, which also gives the relaxation volume) and $\Delta n_i$ is the change in the number of atoms of element $i$. With a one-element bulk, $\mu$ is its energy per atom; otherwise give \textbf{Chemical potentials} as \code{\{"Ni": -4.44\}} for every element added or removed (they set the reservoir the atoms come from). Use the same supercell for both cells and converge its size, since periodic images of the defect interact; charged defects and their corrections are not treated. For a pair potential an unrelaxed vacancy costs exactly the cohesive energy per atom, a useful check.
\item \textbf{Surface, grain-boundary and stacking-fault energy.} $\gamma = (E_\mathrm{cell} - \tfrac{N}{N_\mathrm{bulk}} E_\mathrm{bulk}) / (n A)$ in J/m$^2$ (and eV/\AA$^2$): a slab with vacuum has $n = 2$ free surfaces, a periodic bicrystal from the grain-boundary builder has two boundaries, and a stacking-fault cell one fault. $A$ is spanned by the two cell vectors other than the normal axis (default c). The cell must contain a whole multiple of the bulk composition; both are relaxed with the cell fixed, so the in-plane lattice stays that of the bulk. Converge slab and vacuum thickness (the energy should not change with either), and for grain boundaries also sample the relative translations of the two grains.
\end{itemize}

\subsection{Trajectory-averaged structure}
\textbf{Trajectory-averaged g(r), coordination and bond angles} reads a trajectory file frame by frame (with the same streaming as playback, so long runs need little memory) and averages over the frames from \textbf{First frame}, using every $N$th:
\begin{itemize}
\item the partial radial distribution functions $g_{ab}(r)$, the density of $b$ atoms at distance $r$ from an $a$ atom relative to the average density of $b$ ($N_b-1$ for $b=a$), and the total $g(r)$ weighting all pairs; an uncorrelated (ideal-gas) configuration gives $g(r)=1$;
\item coordination numbers within the neighbour cutoff, per element, per element pair (``Cl around Na'') and as a distribution;
\item the bond-angle distribution of all pairs of neighbours of each atom, normalized to unit area per degree (for perfect fcc, 24, 12, 24 and 6 of the 66 first-shell angles at 60$^\circ$, 90$^\circ$, 120$^\circ$ and 180$^\circ$).
\end{itemize}
Frames must be periodic. Choose the cutoff at the first minimum of $g(r)$, skip equilibration with the first frame and thin correlated frames with every $N$th; \textbf{Use loaded trajectory} takes the file open in Trajectory playback.

\subsection{Batch runs, LAMMPS export and project persistence}\label{sec:automation-tools}
\begin{itemize}
\item \textbf{Batches and parameter sweeps.} \code{AtomForge --science-batch BATCH.json --output RESULTS.json [--csv TABLE.csv]} runs one tool many times. The batch names a \code{tool}, a \code{base} request, an optional \code{sweep} (every combination of the listed values is run), optional \code{files} glob patterns (parameter name to pattern) whose matching files are substituted into that parameter, and \code{collect}: dotted result paths such as \code{heat\_capacity\_eV\_per\_K.0} that become CSV columns. By default a failing case records its error in the table and the batch continues (set \code{continue\_on\_error} to \code{false} to stop at the first failure); the command then exits with status 2. Patterns in \code{files} are relative to the batch file, and the run count is limited to 100000.
\begin{lstlisting}
{"tool": "harmonic-thermodynamics",
 "base": {"energies_eV": {"file": "phonons.csv"}},
 "sweep": {"temperatures_K": [[100], [300], [600]]},
 "collect": ["heat_capacity_eV_per_K.0"]}
\end{lstlisting}
\item \textbf{Export to LAMMPS.} Writes \code{data.lammps} (metal units, atom style atomic) and \code{in.lammps} for minimization (optionally with \code{box/relax}), NVT, NPT or NEB with the same potential, temperature, pressure and damping as the native tools. Periodic cells are converted to LAMMPS's restricted triclinic form (a along $x$, b in the $xy$ plane) with tilts reduced by lattice translations, so fractional coordinates are unchanged; open structures get a padded box with fixed boundaries. EAM files map to \code{eam/alloy}, \code{eam/fs} or \code{eam}, and Lennard-Jones to \code{lj/cut} with shifted energy. LAMMPS has no EMT pair style, so EMT leaves a commented placeholder to replace. NEB writes \code{final.neb} and must be run with one partition per image. Dumps include element names, so Trajectory playback reads them directly.
\item \textbf{Projects.} Saving a project keeps the scientific tool inputs and last result, as described in the project section of this chapter.
\end{itemize}

\subsection{Native tools from Python}
\code{atomforge.native} calls every tool of the catalog in the same compiled engine as the desktop, without ASE, pymatgen or other packages:
\begin{lstlisting}[language=Python]
import atomforge as af
from atomforge import native
s = af.load("POSCAR")
sym = native.symmetry(structure=s, output_cell="primitive")
print(sym["international_symbol"], sym["wyckoff_letters"])
primitive = sym.frames[-1]                 # an atomforge.Structure
types = native.structure_type(structure=s)  # position-based tools accept structure=
md = native.nvt(structure=s, calculator={"potential": "Tersoff"}, steps=1000)
native.run("lammps-export", structure=s, task="nvt").write_files("lammps")
\end{lstlisting}
Keyword arguments are the request keys printed by \code{native.catalog()} (or \code{AtomForge --science --catalog}); tool ids with hyphens are also functions with underscores. Structures are \code{atomforge.Structure} objects, a list of structures is a trajectory for position inputs, NumPy arrays are accepted, and files are \code{\{"file": path\}} relative to \code{base}. A result has \code{result} (the JSON result as a dictionary), \code{frames} (structures), \code{velocities}, \code{times\_fs}, \code{files} and \code{write\_files(directory)}; invalid requests raise \code{ValueError} with the engine's message. The engine is the shared library \code{atomforge\_science\_native} installed with AtomForge; set \code{ATOMFORGE\_SCIENCE\_LIBRARY} to its path if it is not found next to the package or the executable.

\subsection{Repeatable commands and Python examples}
The AtomForge executable runs every tool without Python. The twenty shared functions are also exported from \code{atomforge.science}. The catalog command prints their parameter names, defaults and physical assumptions. A request is a JSON object with those parameter names; data references are relative to the request file. Example \code{gap-request.json}:
\begin{lstlisting}
{"energies_eV": {"file": "EIGENVAL"}, "fermi_eV": 5.4}
\end{lstlisting}
\begin{lstlisting}[language=bash]
AtomForge --science --catalog
AtomForge --science band-gap --input gap-request.json --output gap.json --report gap.txt
python -m atomforge.science band-gap --input gap-request.json --output gap.json
\end{lstlisting}
\code{--structures FRAMES.extxyz} additionally saves NEB images, dynamics frames with their velocities, or a primitive cell; \code{--files DIR} writes generated input files such as \code{KPOINTS}.
Existing outputs require an explicit \code{--overwrite}. A failed calculation preserves the previous result. Result JSON stores the tool identifier, parameters and full result. A data reference can select a column or a nested result field:
\begin{lstlisting}
{"file":"profile.csv", "column":1}
{"file":"msd.json", "field":"result.msd_A2"}
\end{lstlisting}
Numerical CSV has no header; NPY loading forbids pickled Python objects.
\begin{lstlisting}[language=Python]
from atomforge.science import mean_square_displacement, diffusion_coefficient
from atomforge.science.workflows import run_tool
msd = mean_square_displacement(unwrapped_positions, timestep_fs=2,
                               max_lag=200)
fit = diffusion_coefficient(msd["lag_fs"], msd["msd_A2"],
                            fit_range_fs=(100, 300), dimensions=3)
print(fit["D_m2_per_s"], fit["r_squared"])
gap = run_tool("band-gap", {"energies_eV": {"file": "EIGENVAL"},
                            "fermi_eV": 5.4})
\end{lstlisting}
Desktop and \code{AtomForge --science} requests select a built-in potential:
\begin{lstlisting}
{"potential": "EMT"}
{"potential": "LennardJones", "epsilon": 0.0104, "sigma": 3.4, "cutoff": 8.5}
\end{lstlisting}
EMT uses the effective-medium parameters of Jacobsen, Stoltze and N{\o}rskov as distributed with ASE. It covers Al, Cu, Ag, Au, Ni, Pd and Pt; its H, C, N and O parameters are illustrative only. Lennard-Jones takes $\epsilon$ in eV and $\sigma$ and the cutoff in Angstrom; its energy is shifted to zero at the cutoff.

\paragraph{Covalent and ionic potentials.} \textbf{Tersoff} (bond order; LAMMPS \code{pair\_style tersoff}) and \textbf{Stillinger--Weber} (two- and three-body; \code{pair\_style sw}) describe covalent solids. Without a file both use built-in silicon parameters (Tersoff, Phys. Rev. B 38, 9902 (1988): $-4.630$\,eV/atom at $a = 5.432$\,\AA; Stillinger and Weber, Phys. Rev. B 31, 5262 (1985): $-4.337$\,eV/atom at $a = 5.431$\,\AA); browse for a LAMMPS \code{.tersoff} or \code{.sw} file for other elements and mixtures (for example SiC). Energies follow the LAMMPS definitions exactly, so published parameter files are used unchanged; every element pair and triplet present must be listed. \textbf{Buckingham + Coulomb} combines pair terms $A e^{-r/\rho} - C/r^6$ with fixed ionic charges for oxides and other ionic solids:
\begin{lstlisting}
{"potential": "Buckingham", "charges": {"Mg": 2, "O": -2}, "cutoff": 10,
 "pairs": [{"elements": ["Mg", "O"], "A": 821.6, "rho": 0.3242, "C": 0},
           {"elements": ["O", "O"], "A": 22764, "rho": 0.149, "C": 27.88}]}
\end{lstlisting}
Coulomb energies, forces and stress are Ewald-summed in periodic cells (accuracy \code{ewald\_accuracy}, default $10^{-6}$; the cell must be charge neutral) and summed directly for open clusters; point charges reproduce the rock-salt Madelung constant 1.74756. All three provide analytic forces and stress, so relaxation with the cell, NPT dynamics, phonons and elastic constants work with them, and \textbf{Export to LAMMPS} writes the matching \code{tersoff}, \code{sw} or \code{buck/coul/long} pair styles (with \code{atom\_style charge} and Ewald k-space for charges, and the built-in silicon parameter files). Fixed-charge and short-range potentials are only as good as their fit: check lattice constants and elastic constants against reference data before production runs.

Embedded-atom-method potentials are read from the standard LAMMPS table files distributed with published potentials (for example the NIST Interatomic Potentials Repository): \code{setfl} (\code{pair_style eam/alloy}), Finnis--Sinclair (\code{eam/fs}) and single-element \code{funcfl} (\code{eam}). In the dialog choose \textbf{EAM / Finnis-Sinclair file} and browse for the file; in a request write \code{\{"potential": "EAM", "file": "Cu01.eam.alloy"\}} with an optional \code{"format"} (\code{auto}, \code{setfl}, \code{fs} or \code{funcfl}; \code{auto} uses the file name). Relative paths are resolved beside the request file. Elements are matched by chemical symbol, the file's cutoff is used, and densities above the tabulated range continue linearly as in LAMMPS. Tables are interpolated with the same cubic scheme as LAMMPS, so energies and forces agree with LAMMPS for the same file. An EAM potential is only as transferable as its fit; check its intended phases and properties. None of the built-in potentials is universal. Earlier requests written as \code{\{"module":"ase.calculators.emt", "attribute":"EMT"\}} are still accepted. The direct Python simulation functions and \code{python -m atomforge.science} accept configured ASE calculators instead. For NEB the direct Python interface takes a callable that returns a new calculator for each image.
